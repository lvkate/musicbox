# NEMbox/

## Responsibility
The `NEMbox/` package is the core library of NetEase-MusicBox: a CLI/curses TUI client for NetEase Cloud Music. It provides (a) an HTTP API client for music.163.com with encrypted request/response handling, (b) a curses-driven terminal UI, (c) two playback backends (mpg123 and mpv) plus an optional desktop-lyrics overlay, (d) a resident playback daemon exposing JSON-RPC over a Unix socket, and (e) an agent-friendly stateless CLI. It owns session state persisted to `~/.netease-musicbox` (config.json, database.json, cookie.txt) and caches audio into the XDG cache directory.

## Design
- **Singleton pattern**: `Singleton` (singleton.py) is subclassed by `Config`, `Cache`, and `Storage` so a single shared instance holds configuration, the download queue, and persisted database state.
- **Dual API request strategy** (api.py `NetEase`): legacy `weapi` requests are encrypted via `encrypted_request` (AES-128-CBC with a random secret + RSA for `encSecKey`); newer `eapi` requests go through `interface.music.163.com` using `eapi_encrypt`/`eapi_response_decrypt` (AES-ECB, PKCS7). `CachedSession` (requests_cache) caches responses for 3600s; a `MozillaCookieJar` persists login/device cookies per-user.
- **Device & session model**: device IDs (52-char hex) and a stable CN X-Real-IP are derived from the device id; anonymous device registration (`register_anonimous`) and a split-flow QR login (`login_qr_key` → `login_qr_url` → `login_qr_check`) replace password login.
- **Daemon pattern** (daemon.py `MusicboxDaemon`): a double-forked `musicboxd` process owns the single `Player` and `database.json`. A per-uid `flock` single-owner lock (`acquire_lock`/`release_lock`) is shared with the TUI, making TUI and daemon mutually exclusive. Control is JSON-RPC (newline-delimited) over a Unix domain socket (`send_request`). Headless `NullUi` prevents `curses.initscr()` inside the daemon. `spawn_daemon`/`stop_daemon`/`is_daemon_running` manage the lifecycle.
- **Strategy pattern for playback** (player.py `Player`): selects `mpv` (FLAC/hires or configured) vs `mpg123` (mp3). mpv is driven over an IPC Unix socket (`_send_mpv_command`/`_request_mpv_property`); mpg123 is driven over a subprocess stdin text protocol. A class-level `playback_token` + `_is_current_playback` guard races out-of-order async playback callbacks.
- **State-machine navigation** (menu.py `Menu`): the TUI is a cursor/stack machine over a `datatype` enum (main, songs, fmsongs, djprograms, artists, albums, playlists, toplists, search, comments, help, …). A `self.stack` of `(datatype, title, datalist, offset, index)` frames enables hierarchical backtracking; `choice_channel`/`dispatch_enter` push frames; `back_page_event`/`presentHistory` pop them. Navigation retains configurable Vim keys while adding fixed P0/P1 dual bindings, including layered Esc handling.
- **Coroutine-based input parsing** (cmd_parser.py): `cmd_parser`/`erase_coroutine` are generator managers primed by the `coroutine` decorator; `parse_keylist` interprets numeric prefix + nav key chords (next/prev song, up/down) into `(count, keycode)` tuples. `ALT_KEYS` and `match_key()` combine fixed curses special-key aliases with the configurable `KEY_MAP` character bindings.
- **Observer/callback hooks**: `Player.playing_song_changed_callback` syncs the TUI view on track change; `fm_callback` fetches new private-FM tracks; per-track `on_exit` write paths cache downloaded song paths; `end_callback` customizes end-of-queue behavior per list type.
- **Graceful degradation**: `osdlyrics` and `dbus` are imported optionally and degrade to no-ops when Qt/dbus is absent.

## Flow
- **TUI launch** (`__main__.start`): if `sys.argv` is present, `cli.main(argv)` runs; otherwise `daemon.is_daemon_running()` is checked (exits `4` if `musicboxd` is up, since TUI and daemon are mutually exclusive), then `daemon.acquire_lock()` (flock) is acquired and `Menu().start_fork(__version__)` forks — the child runs `update_alert` version check while the parent runs `Menu.start`. `SIGINT`/`SIGTERM`/`SIGWINCH` are wired (`send_kill`, `change_term`).
- **TUI key loop** (`Menu.start`): `screen.getch()` → key is routed into `cmd_parser` generator → `parse_keylist` resolves chords → `KEY_MAP`/`match_key()` dispatch calls `space_key_event`/`enter_page_event`/`up/down_key_event`/`next/prev_key_event` etc. Navigation builds the next `datatype`/`datalist` via `NetEase` + `Parse`/`dig_info`; playback invokes `Player.new_player_list` → `play_or_pause` → `start_playing`. `Ui.build_key_hints()` draws context-sensitive bottom hints after menu rendering and hides them for short terminals or when `key_hints` is disabled.
- **Playback**: `start_playing` resolves the URL (preferring cached file if `args["cache"]` exists on disk), spawns `run_mpv`/`run_mpg123` on a daemon thread, and separately spawns cache + lyric/tlyric download threads. mpg123 parses `@F`/`@E`/`@P` stdout frames to advance location; on end-of-stream the mode logic (ordered/loop/single/random) advances `idx` via `next_idx`/`prev_idx` and replays.
- **Daemon JSON-RPC**: CLI/daemon control commands → `cli._rpc` → `daemon.send_request` (newline-JSON over Unix socket) → `MusicboxDaemon._handle_conn` → `_dispatch` → handler (e.g. `player.play` → `_play` → `Player.new_player_list`/`replay`; `queue.add` → `Player.append_songs`). Each response is an `{ok, data|error}` envelope; daemon errors carry `{type, message, hint}` mapped to CLI exit codes by `_ERROR_EXIT_CODES`.
- **Stateless CLI data commands**: `search`/`song info|url`/`playlist show`/`toplist [--index]`/`recommend songs|playlists`/`fm`/`comments`/`like`/`auth status|login|logout`/`artist`/`album` call `NetEase` directly (`dig_info` batches `songs_url` in 350s and `songs_detail` in 500s, joining by id→index). `auth login` is the QR split-flow: `--no-wait` prints ASCII QR + unikey, `--check <unikey>` polls `login_qr_check`. `download` (`--artist/--album/--songs/--playlist`) resolves URLs via `songs_url` and streams to disk with `requests`; `config get|list` reads `Config` locally without touching the daemon.
- **Caching**: `Cache.add` enqueues `(song_id, song_name, artist, url, on_exit, song_type, level)`; `Cache.start_download` (own thread) pops entries, re-resolves URLs (`NetEase.songs_url`), and shells out to `aria2c` (fallback `wget`) into the XDG download dir; `infer_cache_extension` picks `.flac`/`.mp3` by type/level/URL.
- **Persistence**: `Storage.load`/`save` read/write `database.json` (user, collections, songs, player_info) on every non-status RPC; `Config.save_config_file` writes `config.json`; `create_config()` (`__init__.py`) bootstraps directories/files at import. `Config` exposes the `key_hints` setting (default `True`) for the bottom key-hint bar.

## Integration
- **Entry points**: package entry `NEMbox.__main__.start` (dispatches TUI vs CLI); `NEMbox.cli.main(argv)` (CLI subcommand parser/dispatcher); `NEMbox.daemon.MusicboxDaemon.serve` / module `daemon.main` (`musicboxd` double-fork).
- **Intra-package dependencies**: `__init__` → `const`, `utils`; `cli` → `api`, `config`, `storage`, `daemon`; `daemon` → `api`, `const`, `player`, `storage`; `menu` → `api`, `cache`, `cmd_parser`, `config`, `osdlyrics`, `player`, `storage`, `ui`, `utils`; `player` → `api`, `cache`, `config`, `storage`, `kill_thread`, `ui`, `utils`; `cache` → `api`, `config`, `const`, `singleton`; `api` → `config`, `const`, `encrypt`, `logger`, `storage`.
- **External dependencies**: `requests`/`requests_cache` (HTTP + caching), `Cryptodome.Cipher.AES` (encrypt), `curses` (TUI), `dbus`+`qtpy`/`PyQt` (optional osdlyrics), `rapidfuzz` (fuzzy search), `qrcode` (QR login rendering), `argparse` (CLI).
- **Hooks/events**: signals `SIGWINCH`→`change_term`, `SIGINT`/`SIGTERM`→`send_kill` (cleanup + exit); D-Bus service `org.musicbox.Bus` iface `local.musicbox.Lyrics` (`refresh_lyrics`, `exit`) driven by `Ui.build_process_bar` when osdlyrics is enabled; XDG runtime dir (`runtime_dir`), Unix socket (`socket_path`), and flock (`lock_path`) coordinate daemon/TUI exclusivity and RPC.
